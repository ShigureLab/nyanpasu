# Prompt 改动评估

用冻结的旧新对照判断收益。先考虑精简现有流程和指令；测试通过、措辞更明确、指令更长或单次命中都不能证明行为改善。

## 选择可判定的实验

- 写明待验证的行为假设和可能的退化，再选案例。审查指引使用真实历史问题、不同根因的回归案例和经核实的干净对照；涉及复审时加入“发现问题 → 作者修订 → 继续审查”的连续场景。
- 运行前冻结案例范围、判据、重复次数、预算和旧新运行顺序。关键场景做成对重复，交错运行两组；不为得到理想结果不断追加样本。调优用过的案例属于回归集，泛化结论需要未参与调优的案例。
- 优先复用 [评估说明](../../../evals/reviewer/README.md) 和 [真实 PR 工具流程](../../../evals/reviewer/real-pr/README.md)：`scripts/reviewer_eval.py` 提供 `list-cases`、`prepare` / `prepare-case`、`record` 和 `report`。先查询案例就绪状态，参考记录不当作可运行案例。其他 agent prompt 沿用下述方法，选用对应的真实任务入口。

## 冻结输入与执行条件

- A 为改动前版本，B 为候选版本。保存源码 revision / diff、完整已渲染指令及引用文件的哈希，确认只有待测改动不同。只覆盖入口文本却让两组读取同一份当前引用文件，不构成有效对照。
- 固定 backend、model、reasoning、运行时版本、依赖、工具权限、记忆设置、并发和每案例预算；记录需求、来源及可见时间，固定 base/head。重建的中性需求须标明来源，不冒充原始 PR 描述。
- 每组、每次重复使用独立 runtime 和原生后端 home，产物保存在仓库外。只提供当轮可见的源码和证据；评分答案、其他组输出、未来修订及无关评论/记忆不进入模型输入。不要把有未来对象的完整 Git 历史直接交给首轮。
- 通过真实后端执行。复审在同组保留原生 thread 和已有审查计划，核对续接身份；组间和重复间使用新会话。两组使用相同离线适配，不能把待测机制适配掉后仍声称测到了它。
- 冻结每轮输入、最终报告、原生记录、工具证据、thread/turn 身份和耗时；费用仅在有来源时记录。失败、超时、续接中断及重试单列，不静默替换或算作正确审查。环境失败不当作行为失败。

## 按证据裁决

- 判分时隐藏组别，逐项对照冻结源码、调用契约和必要的独立复现；不要让执行模型自评。若裁判已知组别，如实披露。关键词、finding 数量和报告长度不算命中。
- 缺陷必须有可达触发、后果和源码/实验依据；精简建议必须保留真实契约。按根因去重，区分有效发现、误报、有害建议和证据不足。对复审确认旧问题退出当前 findings，同时检查仍存在或新引入的受影响问题，不能以“旧问题已修复”代替当前版本审查。
- 额外有效发现独立计入，不为迎合预设答案判成误报。若干净对照实际存在缺陷，记录证据并撤回它的干净属性，不追改冻结的主目标分母，也不再据此宣称测得干净 PR 误报率。

## 汇报与结论

报告保留实验 manifest、逐轮原始输出、裁决证据及汇总链接，并说明：

- 案例总量、所选范围、未运行/未裁定/失败范围和重复次数。
- 确认目标检出率及分母、漏检后批准、误报/有害建议、有效精简；复审另报旧问题退出和剩余问题检出。缺陷全集未知时不声称整体召回率。
- 耗时、工具使用和可核实费用，以及与旧版的收益和退化。总耗时不冒充首个有效反馈延迟。
- 实际覆盖的机制。局部 source snapshot 是校准；离线原生回放不等于线上 GitHub、Dashboard、共享记忆或托管子任务生命周期。未覆盖的待测机制需要对应集成验证。

结论区分“有改善证据”“出现退化”“证据不足”，与样本量和覆盖范围相称。小样本的正向迹象不证明稳定提升；仍能复现的问题不能标记已修复。候选可以因更简单、职责更清楚而保留，但须把维护性收益和行为质量结论分别说明。
