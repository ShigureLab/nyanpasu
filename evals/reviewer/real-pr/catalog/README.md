# Real PR candidate catalog

This is an evaluator-only feasibility seed collected on 2026-10-21. It contains 12 candidates with 37 short evidence summaries, four source timelines with 19 events, and three proposed lightweight probes. It contains no raw comment bodies, execution results from a model comparison, or ready-to-run historical-review manifests. Give reviewers only a separately prepared input; this directory contains later discoveries and proposed answers.

- `candidates.json` preserves public source links, full base/head/merge-base identities, selected historical objects, root-cause groups, and reconstruction/adjudication limits. Current base and merge-base remain separate, particularly for Relax #343 and #463. Object availability records the collector's observation and must be refreshed in the checkout supplied with `--repo`.
- `timelines.json` retains review commit bindings and source creation/edit times with paraphrased claims. It does not preserve original historical messages. A reply's bound commit can be older than the fix it describes; do not treat that binding as the current head. Reconstruct the actual permitted source text before using any event in a replay.
- `smoke-plans.json` proposes Nyanpasu #48 metadata checking, #36 test-contract inspection, and #39 closure-discovery replay. These are plans with explicit execution limits. The standard tool stages neutral commits, so #48 needs the original selected commit metadata supplied separately; synthetic commit messages cannot establish the original trailer's presence or absence.

Collection used the GitHub connector, REST review bindings, and read-only Git object/diff inspection. These files compact that source collection; no repository code or behavioral tests were executed while assembling them. No source statement about a reproduction is silently promoted to an independently reproduced fact. Account identity does not establish human authorship: known automation accounts and agent disclosures are marked; other user-account statements remain unverified as to authorship.

One narrowly adjudicated fact is retained: the claim that Nyanpasu #48's reviewed commit `b38d8b8e41c65c3908efc0e81b4af64c97fc4328` lacks a Codex co-author trailer is contradicted by that immutable commit message. The commit message was checked again during catalog assembly. This does not certify any other claim or the whole PR. Nyanpasu #36's assertion replacement and Relax #391's acceptance-JSON deletion were inspected as diffs during collection; runtime implications still require adjudication. Merge, APPROVED, resolved, accepted, and green CI are not labels. The Relax #258 source sequence explicitly illustrates why an approval is insufficient.

Every candidate has `original_pr_body_reconstructed: false` and `ready_for_blind_full_pr_replay: false`. Evaluator summaries draw on current descriptions/discussion and must not be represented as original requirements. A neutral snapshot smoke may use the explicit `evaluator_neutral` provenance supported by the replay tool, with its actual authorship time and the original-requirement gap retained. That is a narrower experiment than historical replay.

Split by root-cause family and keep all revisions together: Relax #258/#391 share the product-versus-acceptance-artifact issue, #285/#290 share the effective-token contract, and Nyanpasu #38/#55 share toolchain/generated-lock scope. Never train on a fix while treating its parent as an independent holdout. #36/#48 and the product-boundary group are calibration candidates; other groups remain provisional holdouts. If #39 is used for calibration or smoke now, move its entire closure-discovery family out of holdout. This seed is neither a balanced benchmark nor evidence of a quality improvement.
