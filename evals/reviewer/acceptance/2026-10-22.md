## Interpretation and rollout

Results use at-least-once delivery. An interrupted receiving turn may receive an unacknowledged result again; a parent must check existing side effects before repeating them. The v4-to-v5 migration can redeliver an old result for an active parent whose consumption was not previously recorded. Root/tree concurrency and context leases retain their prior scope.

The real-PR catalog is an evaluator seed, not an adjudicated benchmark. Historical replay and native lifecycle checks do not establish improved defect recall, fewer harmful suggestions, or fewer review rounds. The generic offline task also does not cover the complete GitHub review intake/publication lifecycle. Those claims require independently adjudicated repeated runs with reconstructed historical requirements.

Deploy only after the live service has no queued, running or waiting tasks and no active context leases. Back up configuration and SQLite before moving the live checkout to the stack top, then verify health, authenticated Dashboard/runtime APIs, retained task/context identities, schema v5 and a clean completed poll cycle.
